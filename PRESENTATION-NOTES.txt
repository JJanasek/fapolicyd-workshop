fapolicyd Power Users — slide notes (English)
================================================================================
Use with presentation.pdf. Same titles as the slides. Then do EXERCISES.md.

Audience: SELinux / policy people. Focus = configure trust, rules.d, conf;
triage FANOTIFY vs AVC. Not an intro to MAC.

Glossary
--------
trust DB      known files (path + size + hash); rpmdb + filedb
rules.d       first-match allow/deny policy fragments
compiled.rules  assembled policy — never edit by hand
FANOTIFY      fapolicyd denial (ausearch -m FANOTIFY)
AVC           SELinux denial (ausearch -m AVC)
pattern=ld_so special subject: dynamic-linker smuggle path


================================================================================
WHY
================================================================================

SELinux asks: given labels, is this access allowed? (behavior)
fapolicyd asks: is this file a known artifact? (trust / provenance)

Use both. One Permission denied can be AVC, FANOTIFY, or both.

You gain: block unpackaged home/tmp/opt code; stop ld.so smuggling;
whitelist by trust, not “it has bin_t”.

Honest limits: root can disable it; not a MAC substitute.


================================================================================
WHAT YOU CONFIGURE
================================================================================

Three places:
  1) Trust DB     — known files
  2) rules.d/     — who/how policy (first match)
  3) fapolicyd.conf — permissive, integrity, tuning

Path: open/exec → fanotify → fapolicyd (trust + rules) → allow/deny

Hard rule: never strace/gdb/ptrace the daemon (SIGSTOP → deadlock).

Trust backends: rpmdb (RPM + plugin) and filedb (you, under trust.d/).
Rules recipe:  decision  permission  subject : object
Integrity: none (default) → size (pragmatic) → sha256 (expensive).


================================================================================
CONFIGURE
================================================================================

A — Install
  dnf install fapolicyd fapolicyd-selinux rpm-plugin-fapolicyd
  ≥1 audit rule (else deny_audit is quiet): auditctl -w /etc/shadow -p w
  systemctl enable --now fapolicyd
  fapolicyd-cli --check-status / --list

B — Trust unpackaged /opt (default remediation)
  fapolicyd-cli --file add /opt/myapp --trust-file myapp
  fapolicyd-cli --update
  Prefer trust trees over allow-rule sprawl.

C — rules.d drop-in (when you need who/how, not just “known”)
  Number file above catch-all deny (e.g. 55-… before 90-…).
  fagenrules && fapolicyd-cli --check-rules --lint && systemctl reload fapolicyd
  Bad candidate → previous ruleset kept.

D — Conf
  permissive=1 soak → fix → permissive=0
  integrity=size before sha256

Denied?
  1) ausearch -m AVC
  2) ausearch -m FANOTIFY -i
     Compact FANOTIFY often has NO path (-f may miss).
     Path + rule:N → foreground --debug-deny
  3) unclear → stop service; fapolicyd --permissive --debug-deny; reproduce

FANOTIFY deny:
  Should be known software? → trust + --update
  Who/how exception? → rules.d

Anti-patterns: allow sprawl; edit compiled.rules; assume SELinux allow ⇒ fapolicyd allow.
