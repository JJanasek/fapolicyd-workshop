Glossary
--------
trust DB      known files (path + size + hash); rpmdb + filedb
rules.d       first-match allow/deny policy fragments
compiled.rules  assembled policy — never edit by hand
FANOTIFY      fapolicyd denial (ausearch -m FANOTIFY)
AVC           SELinux denial (ausearch -m AVC)
pattern=ld_so special subject: dynamic-linker smuggle path


================================================================================
WHY
================================================================================

Beside SELinux, not instead:
  SELinux = behavior (labels). fapolicyd = known artifact? (trust).
  Layered: SELinux is asked first, first denier wins.

You already know most of this (mapping table):
  This is the slide to slow down on. Two rows deserve a sentence each:
  - Order. SELinux allow rules form a set; fapolicyd is first match.
    Moving a file in rules.d changes policy.
  - No audit2allow. The fix for "known software denied" is trust, not a
    generated rule.
  Error text differs: SELinux/DAC = "Permission denied" (EACCES),
  fapolicyd = "Operation not permitted" (EPERM).

Where it sits in an exec (diagram):
  DAC → SELinux → fanotify permission event → fapolicyd.
  The SELinux execute check happens while the file is being opened for
  exec; the fanotify event comes after. A denial at any box ends the
  attempt, so later boxes log nothing.
  Dashed boxes are what you configure: trust sources and rules.

What it does not stop:
  Say this before they ask. Shell scripts are allowed by default.
  ld_preload and static patterns ship commented out in 30-patterns.
  Unwatched filesystems (watch_fs, ignore_mounts) are invisible to it.
  Trusted interpreters still act on whatever data they are given.
  Root can stop or reconfigure it.


================================================================================
WHAT YOU CONFIGURE
================================================================================

Four places:
  1) Trust DB   2) rules.d/   3) fapolicyd.conf   4) fapolicyd-filter.conf

Hard rule: never strace/gdb/ptrace the daemon.
  SIGSTOP means no permission event gets answered.
  2.0 service is Type=notify, WatchdogSec=10s, Restart=on-failure, so
  systemd can restart a stalled daemon. Do not rely on it.
  Nice for this audience: fapolicyd-selinux ships fapolicyd-hardening.cil
  with a CIL deny rule: (deny domain fapolicyd_t (process (ptrace sigstop))).

Trust: rpmdb (kept current by the rpm plugin) + filedb (trust.d/).
  Entry = source, path, size, hash. Rules only see trust=1 / trust=0.
  Hashes: SHA256 or SHA512; rule keyword FILE_HASH replaces SHA256HASH.

Filter: fapolicyd-filter.conf (+ include / - exclude). Applied at trust
  import, not per decision. Also --file add PATH --filter.
  fapolicyd-cli --test-filter PATH. Not drilled.

Rules: decision  permission  subject : object   (first match)
  Decisions: allow / deny, plus _audit, _syslog, _log (audit + syslog).

Shipped ruleset (two slides) + "who wins?":
  Read it top to bottom once, out loud. Then use the "who wins?" table as
  a quiz: cover the right-hand columns and ask the room.
  Points to make:
  - 20-dracut is why root "bypasses" denials: uid=0 AND trusted subject.
  - 21-updaters keeps rpm/dnf from being blocked mid-transaction.
  - 30-patterns denies ld.so-started programs, trusted or not.
  - 41 comes before 42 because every exec loads a dozen libraries.
  - 70 denies untrusted language files; 72 allows every shell script.
  - 90 is the catch-all for execute; 95 lets everything else be opened.
  - A drop-in at 55- cannot restrict a trusted binary: 42 already allowed it.

New in 2.0: path=glob:/opt/vendor/*/bin/tool (exe/path only, * stops at /);
  double quotes for spaces; %languages+=mime for packages;
  dir=untrusted deprecated. fapolicyd-cli --ftype FILE for ftype= rules.

Conf: permissive=1 soak → fix → 0. integrity none|size|ima|sha256.
  Newer: decision_threads (2.0), ignore_mounts, db_max_size=auto,
  rpm_sha256_only, reset_strategy, timing_collection.


================================================================================
CONFIGURE
================================================================================

A — Install and verify
  dnf install fapolicyd pulls the rpm plugin and fapolicyd-selinux.
  F44 / 2.0.1: separate rpm-plugin-fapolicyd package.
  Rawhide 2.0.2: fapolicyd ships the plugin, Obsoletes rpm-plugin-fapolicyd < 7.
  ≥1 audit rule, else deny_audit is quiet:
    auditctl -a always,exit -F path=/etc/shadow -F perm=wa
  fapolicyd-cli --check-status → Permissive: false, trust entries > 0.

B — Trust /opt (default remediation)
  --file add /opt/myapp --trust-file myapp && --update
  Prefer trust trees over allow-rule sprawl.

C — rules.d (who/how, not just "known")
  Example: rules.d/39-ping.rules, gid=fapo_workshop (not wheel — fapo is in wheel).
  One physical line per rule.
  Apply: fagenrules --load   (NOT systemctl reload — no ExecReload).
  Or: fagenrules && fapolicyd-cli --reload-rules
  Then --check-rules --lint → --list (ping lines above 42).
  Failed in-daemon reload keeps previous ruleset.
  Test as fapo. Root hits uid=0 trust=1 first.


================================================================================
TRIAGE
================================================================================

Denied?
  1) Error text: EPERM = fapolicyd, EACCES = SELinux/DAC
  2) ausearch -m AVC
  3) ausearch -m FANOTIFY -i
     known software → trust; who/how → rules.d
  4) Unclear → deny_log or --debug-deny

Reading the records:
  FANOTIFY record, kernel >= 6.3: resp (2 = deny), fan_info = rule number
  in HEX (same numbering as fapolicyd-cli --list), subj_trust / obj_trust
  (0 no, 1 yes, 2 unknown).
  Daemon line: rule=N dec=… perm=… auid=… pid=… exe=… : path=… ftype=… trust=…
  The values on the slide are illustrative. Replace them with a record
  captured on the lab VM if you have one.

Dual stack: one binary can be wrong for BOTH layers.
  Wrong label → AVC first; untrusted → FANOTIFY next. One attempt
  normally logs only the first denier. Fix each layer.
  Lab: type tmp_t. user_tmp_t is executable by staff_t while
  staff_exec_content is on (default).
  restorecon on /var/tmp often does nothing (file_contexts <<none>>).

Debug:
  a) Without stopping: rule deny_audit → deny_log, fagenrules --load,
     journalctl -b -u fapolicyd. Prefer this on real hosts.
  b) Foreground: stop; mkdir -p /run/fapolicyd (2.0.1: systemd removes it
     on stop and the daemon needs it for its pid file);
     fapolicyd --permissive --debug-deny; reproduce. Lab only.
  Per-rule hit counts: fapolicyd-cli --check-metrics.

Anti-patterns: allow sprawl; edit compiled.rules; test as root;
SELinux allow ⇒ fapolicyd allow; stopping the daemon on a real host.


================================================================================
FOR MAINTAINERS
================================================================================

How trust stays current:
  rpm/dnf transaction → rpm plugin → /run/fapolicyd/fapolicyd.fifo → daemon
  rebuilds the trust DB (LMDB, /var/lib/fapolicyd).
  21-updaters exists to avoid the updater/daemon deadlock.
  Failed reloads keep the active generation (1.5 rules, 1.6 trust).

fapolicyd-selinux:
  fapolicyd_t is an init daemon domain. It is broad by necessity:
  files_read_all_files, files_mmap_all_files, domain_read_all_domains_state,
  watch_with_perm on all file types, capabilities sys_admin / sys_ptrace /
  dac_override. Worth a discussion: what can be tightened?
  fapolicyd-hardening.cil is a separate optional module.

Source tour: src/daemon, src/library, src/cli, src/tests (+ stress,
perf-test), rules.d/, ChangeLog.
